# DenguYosoku (デング予測)

Leak-free weekly dengue nowcasting for **77 Thai provinces**. LightGBM with the
training loss matched to the pre-registered metric, two rebuild leakage proofs,
three naive baselines, and a paired week-bootstrap confidence interval.

> **Sealed 94-week holdout** (2025-01-05 → 2026-10-18, 7,238 province-weeks)
> MAE **3.518** cases vs persistence **3.964** → **+11.3 % skill**
> Paired ΔMAE **−0.446**, 95 % CI **[−0.650, −0.301]** → verdict **REAL**
>
> Every number is regenerated into `DenguYosoku/metrics.json`. If this README
> and that file disagree, **trust `metrics.json`**.

## Try the trained model — 30 seconds, no training, no full dataset

The repo ships the fitted model and a 77-row demo week, so this works on a fresh clone:

```bash
pip install -r requirements.txt
python plot_all.py predict_2026-10-25
```

That reads `predict_week/predict_2026-10-25.csv` (12 features, **no `cases` column** —
the answer is structurally absent, so the model cannot cheat), scores it with
`DenguYosoku/model.txt`, and writes `predict_week/predictions.csv`.

Score it against the truth and draw the comparison figures:

```bash
python plot_all.py predict_2026-10-25 blind_compare_hist plot_DenguYosoku
```

| What you get | Where |
| --- | --- |
| Per-province forecasts for the blind week | `predict_week/predictions.csv` |
| Actual vs predicted bars, 5 largest / 5 smallest gaps | `blind_plots/` |
| Full 77-province error ranking | `blind_plots/blind_comparison_77.csv` |
| The 11-figure holdout deck + 77 province panels | `DenguYosoku_plots/` |

The eight plotting/prediction scripts are **embedded inside `plot_all.py`**, so you
do not need separate copies of them. `DenguYosoku.py` and `make_blind_holdout.py`
are *not* embedded and must exist as files.

```bash
python plot_all.py --list                     # show the 8 embedded scripts
python plot_all.py skew_report skew_split     # run a subset
python plot_all.py --stop-on-error            # halt on first failure (default: keep going)
```

Each embedded script runs in its **own fresh Python subprocess** — same interpreter,
working directory, environment and argv as a standalone run. No matplotlib, seaborn
or font state leaks between scripts, so every PNG/CSV is exactly what the standalone
script writes.

### About `answer_key.csv`

`make_blind_holdout.py` was designed to keep this file private ("GIVE FRIEND:
predict + features + model; KEEP PRIVATE: answer_key"). This repo publishes it
deliberately, so anyone can verify the blind-week MAE independently.

| Mode | `answer_key.csv` | Consequence |
| --- | --- | --- |
| **Reproducible benchmark** (as shipped) | committed | anyone can score the demo; blind property is spent |
| **Live blind test** | withheld | a friend can predict honestly, but cannot self-score |

The demo week is historical and the model is frozen, so publishing is defensible.
To switch to a live blind test, remove `answer_key.csv` and drop its `!` line from
`.gitignore`.

## Install

```bash
git clone https://github.com/johnlovepizza/DenguYosoku.git
cd DenguYosoku
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # core only — runs the whole pipeline
```

Core is five packages: `numpy`, `pandas`, `lightgbm`, `matplotlib`, `seaborn`.
Python 3.14.9 was used for the reported run.

Everything else is **optional** and commented out in `requirements.txt`. Each
optional import is wrapped in `try/except`, so a missing package prints a notice
and skips that one output instead of crashing the run.

```bash
pip install optuna tqdm                  # only if RUN_OPTUNA=True (False as shipped)
pip install plotly                       # only for the two interactive HTML heatmaps
pip install "plotly>=6" "kaleido>=1.0"   # only for optuna_*.png — also needs system Chrome
```

`matplotlib >= 3.9` is a hard floor, not a preference: `skew_split.py` calls
`ax.boxplot(..., tick_labels=...)`, and `labels` was renamed to `tick_labels` in 3.9.

| Step | What it does | Where in `DenguYosoku.py` |
| --- | --- | --- |
| 1 FRAME | Five written questions; metric fixed *before* modelling | `FRAME` dict |
| 2 AUDIT | Duplicates, 7-day grid, negatives, leaky/broken columns | audit block |

| 8 REPORT | Importance, predictions, `metrics.json` | Step 8 block |

## Data

One row = one province in one epidemiological week (Sunday start).

| Column | Role |
| --- | --- |
| `province`, `week_start`, `week`, `year` | identifiers / calendar |
| `cases` | **target** — weekly reported dengue count |
| `w_apparent_temperature_mean` | weather source, used **lagged only** |
| `population`, `cases_per_100k` | **excluded** — see below |

Two files, both committed:

| File | Read by | Must contain |
| --- | --- | --- |
| `dengue_cut_allweeks_2003-18_Oct_2026.csv` | `DenguYosoku.py` (hardcoded, no fallback), `skew_report.py`, `skew_split.py`, `raw_cases_hist_swapped.py` | full grid through 2026-10-18 |
| `dengue_full.csv` | `make_blind_holdout.py` (hardcoded), both top-5 plot scripts | same history **plus** the blind week 2026-10-25 |

Reported run: **95,634 rows × 1,242 weeks**, 2003-01-05 → 2026-10-18, 77 provinces,
zero duplicate province-weeks, zero grid gaps, zero negative counts. The first 12
weeks per province are dropped as lag warm-up; exact `n_train` / `n_test` are in
`metrics.json`.

**Never used as features**

- `cases_per_100k` — equals `cases / population`, so it contains the target.
- `population` — national total ranges 62 M–385 M against Thailand's ~66 M: a broken
  unit/normalisation column, excluded rather than silently "cleaned".
- `prov_lat`, `prov_lon`, `year_ce`, `week_start` — identifiers, not causal inputs.
- Mosquito indices — sparse, with implausible Breteau values.

Rows are kept; only the columns are excluded. The audit *asserts* zero duplicates
and zero negative counts; grid gaps are reported but not asserted.

> **Provenance / licence:** aggregate provincial weekly counts, no personal data.
> Source: `<provider, version/date>`. Licence: `<licence>`. Fill this in before
> making the repo public — you are redistributing the CSVs.

## Methodology highlights

### Two rebuild leakage proofs, not just name assertions

```
LEAK TEST 1  delete-after-2019-09-29 : changed = 0
LEAK TEST 2  perturb-week-2019-09-29 : moved   = 0
```

The cut week is the 70th-percentile week of the modelling panel, not a fixed date.
**Delete-the-future** rebuilds every feature after truncating the panel; nothing at
or before the cut may move. **Perturb-the-week** changes only the cut week's raw
`cases` and weather; that week's features must not move. `NaN == NaN` counts as
equal, and `prov_baseline` is held fixed as a fitted statistic (like a scaler), so
the tests compare against a stable target.

The blind rehearsal applies the same idea structurally: the answer is **blanked
before any lag is computed**, so no feature can contain it. It then asserts
`cases_L1 == previous week` for all 77 provinces.

### Matching the training loss to the decision metric

MAE is minimised by the conditional **median**. Poisson fits the conditional
**mean**, which on overdispersed counts sits above the median and therefore
over-predicts quiet weeks — and ~11 % of province-weeks have zero cases, which is
also why MAE was chosen over MAPE.

The loss was selected on CV folds only, never on the sealed test:

```
quantile(alpha=0.5) won at every round count
shipped booster: objective=quantile, alpha=0.5, 600 rounds
pinball(0.5) = 0.5 * L1  ->  its minimiser IS the MAE minimiser
```

The switch also changed *what* the model learned: `cases_L1` fell from ~83 % to
**49.8 %** of gain, while the multi-week slope (`cases_L2..L4`, now **33.7 %**) and
the seasonal harmonic gained weight.

RMSE and Poisson deviance are **higher** for the median fit by design — they are
mean-forecast metrics, traded away for the pre-registered MAE.

## Known limitations

Read these before quoting any number.

1. **The shipped model uses LightGBM defaults, not the Step 6 tree shape.** Step 6
   builds a Poisson model at `BEST` — with `RUN_OPTUNA=False` (the shipped setting)
   `BEST` is a *hand-set* config, not a searched one. Step 6b then re-fits at
   `BASE_P` with the loss-matched objective, overwriting both `model` and `iters`.
   `model.txt` confirms it: `num_leaves=31`, `learning_rate=0.1`, `max_depth=-1`,
   no bagging, no column subsampling, no L1/L2. Any Optuna search is exploratory
   only. To ship the Step 6 shape, change the final `lgb.train` to
   `dict(BEST, **CANDIDATES[best_obj], metric="None")` — this changes results and
   requires a fresh disclosure.

2. **The holdout informed more than one configuration** (Poisson, then quantile
   α=0.5). The loss choice was made on CV alone, so selection is honest, but the
   final estimate carries mild optimism from repeated inspection.

3. **Year-straddle reporting anomaly.** The first holdout week (2025-01-05) has
   national actual 821 vs predicted 1,551 — the largest national residual in the
   holdout. The late-December reporting spike propagates through `cases_L1`.
   Isolated from all turning-point statistics.

4. **`prov_baseline` is fitted on the full training period**, so earlier CV folds
   see a denominator built partly from their own future. Test-set evaluation is
   unaffected; CV numbers are mildly optimistic.

5. **This is a nowcast, not a multi-week forecast.** Autoregressive features carry
   **93.7 %** of gain and the output trails turning points by one week.

6. **The blind rehearsal reads a different file than training.**
   `make_blind_holdout.py` has `SRC = Path("dengue_full.csv")` while
   `DenguYosoku.py` trains on the `allweeks` cut. If the two disagree on the last
   12 weeks per province, the blind week's lags differ from training-time
   features. Verify the tail matches, or point `SRC` at the training file.

7. **The blind filename is dynamic on one side, hardcoded on the other.**
   `make_blind_holdout.py` writes `predict_{LAST.date()}.csv` from `dengue_full.csv`'s
   max week; the prediction step hardcodes `predict_2026-10-25.csv`. So
   `dengue_full.csv` must end exactly at **2026-10-25** — the week `DenguYosoku.py`
   drops via `EVAL_CUTOFF`.

8. **The decile table in Step 7 is binned by ACTUAL**, so it shows
   regression-to-the-mean tilt even for a calibrated model. The honest calibration
   check bins by PREDICTION; the overall bias is printed alongside for that reason.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| `SyntaxError` in standalone `predict_2026-10-25.py` | That copy has whitespace damage inside string literals. Use `python plot_all.py predict_2026-10-25` — the embedded copy is normalised. |
| `ERROR: run DenguYosoku.py first` | `DenguYosoku/holdout_predictions.csv` missing. Run `python DenguYosoku.py`. |
| `ERROR: dengue_full.csv not found` | The top-5 scripts need it for the history curves. It is committed at repo root; run from that folder. |
| `no CSV found` in a skew script | Pass the path explicitly: `python plot_all.py skew_report` after setting `ARGS["skew_report"] = ["<path>"]`, or run the standalone script with the path as its first argument. |
| Thai province names render as boxes | Install a Thai font (`Noto Sans Thai`, `Sarabun`, `Loma`, …). Scripts fall back to DejaVu Sans and print which font they picked. |
| `optuna_*.png` missing | Expected: HTML is always written, PNG needs `kaleido` + system Chrome. |
| Feature-importance plot says "11 features" | Cosmetic label bug in `plot_DenguYosoku.py`; there are 12. The bars themselves are correct. |
| `plot_all.py` docstring says "7 scripts" | Cosmetic; it runs 8. `--list` shows the truth. |

## Reproducibility

| Item | Value |
| --- | --- |
| Seed | 42 (NumPy, LightGBM) |
| Threads | 1 — LightGBM histogram binning is non-deterministic across threads |
| Split | `TRAIN_END = 2025-01-01`, `EVAL_CUTOFF = 2026-10-25` |
| CV | 5 expanding folds, 4-week purge gap, `MIN_TRAIN_FRAC = 0.45` |
| Search | `RUN_OPTUNA = False` as shipped |
| Shipped model | quantile α=0.5, 600 rounds, LightGBM default tree params |
| Bootstrap | 4,000 resamples of whole **weeks** (provinces within a week are correlated) |
| Metric | MAE vs persistence, fixed in Step 1 before any result |
| Versions | `DenguYosoku/metrics.json` → `versions` |

Re-running with the same config reproduces every number bit-for-bit.

`metrics.json` records python / numpy / pandas / lightgbm — but **not** matplotlib
or seaborn, which is what figures depend on. For byte-identical PNGs, freeze the
whole stack after a verified run:

```bash
pip freeze > requirements.lock.txt
```

The `numpy` / `pandas` / `lightgbm` pins in `requirements.txt` should match
`metrics.json → versions`; if they disagree, trust `metrics.json` and re-pin.
